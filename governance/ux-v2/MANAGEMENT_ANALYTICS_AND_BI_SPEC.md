# Management Analytics / BI Center

Phase 1 proposal; authority is [Issue #2 Management Analytics addendum](evidence/ISSUE_2_ANALYTICS_ADDENDUM.md). All computations below are descriptive server-side analytics over authoritative facts. They do not set Active, rank, placement, K, Carry, Award or destination. No frontend monetary calculation; no AI bonus calculator.

## 1. IA, filters and common metric contract

Admin > 分析中心: Executive, Organization, Performance, Rank & Talent, Bonus, Customer Quality, Finance & Governance. Each domain uses summary cards, trend, comparison table and evidence drill-down. Header always exposes 資料期間, 資料更新時間, basis/version, freshness and scope. Tree and founding filters do not merge Sponsor/Binary scope. Pin filters in URL and returned contextToken; change invalidates all panels together. Empty, unavailable, pending and true zero are distinct. CSV uses the same authorized server query/generation.

Global filters: calendar month/settlement/Binary week, BinaryTree, founding subtree, rankBasis+rank, Active, product/package. Server returns supportedFilters per report. A filter not meaningful for a metric is disabled with explanation, and supplying it returns 422 rather than silently changing the question. Product filter applies source-line population, not “any Ball that ever bought product” unless an explicit purchaser-cohort report is selected. Nonadditive multi-product/Person/tree views must identify overlaps.

The following defaults apply to EVERY dictionary row below, with overrides stated in that row:

* Grain: Qualification/Ball; never implicit Person. MEMBER population means effective member-owned Balls at measurement instant, excluding COMPANY including bootstrap. Operational population includes member-origin company-held Balls once; label separately. Scope contains only authorized rows before aggregation.
* Time: UTC storage, Asia/Taipei calendar boundaries; flow windows `[start,end)`. State at t uses `from <= t < to`; an end-of-period snapshot evaluates immediately before end. `asOf` bounds effective facts; `knowledgeCutoff` bounds recorded facts. Default knowledgeCutoff is explicit query snapshot time. No current-state fallback.
* Corrections: retain immutable source and original economic period; latest-known restated views apply signed linked POSTED/replay corrections once. “Known then” excludes later-recorded corrections. Return posting-month activity is a separate report. Mark affected read generations incomplete until replay converges.
* Precision: sum source Decimal(18,4) without per-row UI rounding; ratios use decimal division, displayed percent to 2 decimals (half-up); source precision is returned. Counts integers. Quantiles/averages returned to 4 decimals for display, never fed back into Core.
* Count/sum metrics have denominator N/A. Rate metrics return numerator AND denominator. Zero denominator -> null/NO_POPULATION; missing numerator/source/history -> UNAVAILABLE, never zero. Partial sources -> incomplete, no official aggregate. Pending awards remain null/pending with separate pendingCount, not zero-income observations.
* Provenance: definitionVersion, applied filters, grain/population, timestamp policy, source table/event IDs or aggregate evidence manifest, rule/parameter/calendar refs, generation, watermark, computedAt, coverage and reconciliation status. A row without these cannot be published as authoritative.

Three partial returns on those same two orders still count two orders. REQUESTED-only third order does not enter numerator. No source orders -> null, not 0%.

## 4. Bonus mix, income bands and concentration

Source mapping: Referral=BonusAward REFERRAL; Referral Matching=EQUALIZATION; Binary=BINARY; Binary Matching=MATCHING; EPV=EPV; RPV may come from RpvUplineAwardEvent/related canonical materialization; Global=GlobalPoolAward. An adapter must identify canonical entitlementKey and avoid counting source plus mirrored Award/Payable as separate income. Unsupported “other” categories remain named by approved award registry, never bundled fabricated money.

For each type expose Theory, Final/materialized, Payable, Paid, Recovery, Clawback, Adjustment as SEPARATE columns. TheoryCalculationEvidence/BonusCalculationEvidence precede final; BonusAward.payableAmount alone does not prove PAID. PayableEntry and reconciled PayoutLine/lifecycle are authoritative for their stages. Monetary lifecycle is not additive: do not sum Theory+Final+Paid. B company entitlements appear in separate destination reports, excluded from member income distribution. Original PAID stays immutable; net-after-recovery is an optional distinct metric.

Distribution population = all eligible MEMBER Ball-period observations under declared period-end population rule, including proven zero-award Balls; retain exited-during-period recipients as explicit separate segment rather than losing their period awards. Return `eligibleCount`, `completeCount`, `pendingCount`, `unknownCount`, `excludedCompanyCount` and reconciliation scope. Finalized basis attributes entitlement to source settlement/event economic period; paid basis attributes actual reconciled payment time. Do not silently mix these populations with tree counts at another instant.

Bands are versioned analytics configuration: exact zero; (0,5000]; (5000,20000]; (20000,50000]; (50000,100000]; (100000,300000]; (300000,1000000]; (1000000,+infinity). This defines decimal amounts without gaps such as 5000.01. UI may show integer-friendly labels only alongside exact bounds. Negative corrections/net values require a separate NEGATIVE band in any net basis. Pending values have no income band. No Core config changes.

For each band: Ball count; share=count/complete population; average=sum/count; exact median; GPV on same Ball-period population; Active rate using stated checkpoint; rank mix using selected rank basis. Band sums and counts reconcile to complete source population, with excluded/pending rows separately accounted. All-zero population has a populated zero band and null concentration share.

Concentration: sort nonnegative complete Ball totals ascending; quantile p uses linear interpolation at index `(N-1)*p`, giving exact median/P75/P90/P95/P99. Top p% selects `ceil(N*p)` highest totals, deterministic Ball-ID tie-break; share=sum(selected)/sum(all). Include zero-income members; do not compute on only paid recipients without declaring a different population. N=0 =>null; denominator 0=>null; N small warns about rounded selection count. Signed net basis with negatives is unsupported for concentration until a separate definition; never clamp silently. Optional Lorenz/Gini DEFERRED until rigorously reviewed. Analytics never caps awards.

Fixture: complete values [0,100,200,300] => count4, median150, P75=225; top25% share300/600=50%. Person owning two of these remains two Ball observations. A fifth PENDING row increases pendingCount only, not a zero band. Exact bounds 5000 and 5000.0001 enter different bands.

All physical keys additionally include definitionVersion and relevant source knowledge boundary. Aggregate rebuild/version strategy is shared with the statistics spec. Event consumers run separately from economic workers; they cannot append Award or alter rule config. Transactionally dedup `(consumer,eventId,generation)`, update facts/aggregate/checkpoint. Source transaction outbox is at-least-once; exactly-once contribution requires durable uniqueness. Out-of-order causal gaps pause source watermark. Late return dirties original economic months, downstream Carry and affected snapshots; complete new generation only after authoritative replay converges. Do not apply raw return amount*rate inside analytics.

Rebuild uses immutable cutoff manifest, replays sorted effective/recorded evidence, validates membership and event uniqueness, compares count/amount checksums against authoritative source queries, then atomically publishes generation. Crash/retry never publishes partial totals. Reconciliation: sum band counts=complete observations; band amounts=canonical basis sum; source recognition totals=tree source facts with explicit unplaced bucket; per-Ball Carry equals settlement/replay; A and B independent; posting vs cohort views reconcile via source mapping. Missing old snapshots quarantines affected period rather than current-state recovery.

Scale goals are unmeasured acceptance targets: 10K use indexed period queries/aggregates; 100K use incremental aggregates and batch exact distribution; 1M+ use period partitions/jobs, projected founding summaries and bounded ancestry, not full closure for pathological chains. Index `(treeId,period,Ball)`, `(sourceId,recordedAt)`, `(rankBasis,checkpoint,rank)`, reverse Sponsor/ancestor and effect/settlement. Interactive page <=100 rows; chart <=366 buckets; longer report asynchronous. Benchmark P95 <=1s cached summaries, <=2s comparison under agreed load; budgets failing cause async/unavailable, not silently truncated populations. Test balanced and skewed trees and correction bursts. Record hardware, query plans, rows scanned, lag and rebuild duration before approval; no claimed 1M performance from node count alone.

## 7. Authorization, deterministic alerts and AI

Analytics capability plus per-domain finance/PII/B permissions; aggregation filters cannot bypass field restrictions. Unprivileged counts over forbidden Balls also forbidden. Person identity masked unless separately authorized. Export reauthorizes and preserves filters; download private/expiring and auditable. Query quotas and asynchronous jobs prevent full-tree exfiltration/resource exhaustion. Audit privileged asOf, export, definition publication and evidence access.

AlertDefinition is versioned analytics config: metricVersion, population/basis, baseline window, comparison operator, threshold, minimum denominator/coverage, consecutive-window count, cooldown and owner. Defaults require reviewed values; do not invent “dangerous” business thresholds. Return-rate spike, K deterioration, Carry concentration, Active decline, Recovery increase and integrity mismatch each emit deterministic ID `(definition,scope,window,generation)` with operands/source refs. Unknown/stale inputs suppress numeric alerts and create DATA_INCOMPLETE. Replay supersedes prior alert evidence rather than deleting it. Alert routes link to review; no automatic financial repair or external messaging in this phase.

AI may Observe -> Explain -> Alert/Recommend using authorized read models; every statement retains scope/period/basis/evidence, marks uncertainty and abstains on missing data. No commands, bonus formula generation, rule editing or automated placement through AI. Descriptive next-rank assistance cannot promote.
