## Findings and repairs

- A recorded contract filter initially dropped envelope meta. Strict Member envelope validation rejected it. Fixed the exporter to preserve the original endpoint metadata and regenerated through a fresh DB run; no frontend validation was relaxed.
- Admin's Node fs fixture reader initially sat inside src/, causing browser TypeScript build errors for Node types. Moved the test to admin/tests/; no Node dependency or Node filesystem code is shipped in the browser bundle.
- The Member order page had no successful-read refresh action. A regression reproduced the absent button. Added 「重新整理訂單」 using the existing scoped loader; it closes stale expanded detail, loads current Core state and disables refresh while loading. The regression confirms that the paid order changes CONFIRMED→PAID and both requests use the same selected ball.
- The first refresh assertion incorrectly rejected any remaining CONFIRMED order, including a distinct newly created unpaid order. Scoped it to the order that was actually paid, preserving the legitimate unpaid record. Initial failures remain under final/initial-attempts/.

## Reproduce

Run pnpm build in backend/ first. Set NODE_ENV=test, ADMIN_AUTH_BYPASS=false and MEMBER_CONTRACT_OUTPUT_DIR to this report's absolute final/ path, then run pnpm db:golden in backend/. Run pnpm test in member/ and admin/ with MEMBER_ADMIN_CONTRACT_FILE set to the newly generated final/member-admin-contract.json. Run pnpm build in both frontends. Tests default to the checked-in isolated response snapshot when no file override is supplied; default replay does not claim a live backend connection. Existing Member ten-response contracts may additionally be tested with MEMBER_CONTRACT_FILE set to final/ball-1.json and final/ball-2.json.
