# NASL 與十二代組織健康雷達：管理定義 v1

日期：2026-09-18。政策版本：`UCELL-MGMT-2026-09-v1`。

依據：產品負責人本次「用一般性管理原則定義，繼續開發與修訂」指示，以及既有 `NEXT_RELEASE_DECISION_BATCH1_APPROVED.md`（004/005）與 Batch 2（006/007/012/013）。本次新增規則是分析層的管理預設，並非已由實證研究校準的預測模型。舊規格中的「NASL／熱度／權重尚待核准」已由這兩份決策文件及本次指示取代。

## 管理用途與邊界

用途：辨識新會員啟動障礙、沉寂風險、重購參與與組織結構的支持需求。建議先調查原因、確認聯絡意願，再安排服務、教育或回訪；不可把分級當作人格、信用、收入能力或懲罰依據。

分析不修改會員身分、Qualification Active、推薦與雙軌關係、獎金、Carry、結算、付款或其他正式帳務。Person 和 Qualification 是不同單位；推薦樹和雙軌樹分開讀取。

## NASL

目前涵蓋已建立 membershipState 的 Person，及持有人員經營球的 Person；未建立會員身分的零球紀錄不計入。僅持有明確指定系統球的專用 Person 排除。系統球目前以 SystemAssignmentPool 的有效指定辨識，並非完整 SYSTEM 所有權登記；待後續所有權模型接入後升級政策。

起算日目前採 `Person.createdAt`，是會員紀錄建立日的代理值，不聲稱法律入會日或首次完成註冊日。同期群月份以 Asia/Taipei 劃分。Closed 使用快照當下 Person.status=CLOSED；不從現在的 Closed 狀態反推歷史關閉日期。

判定優先序：Closed → A → N → S → L。

| 狀態 | v1 定義 | 管理解讀 |
| --- | --- | --- |
| N 新進 | 紀錄建立未超過 30×24 小時，且尚不符合 A | 協助理解產品與首次有效參與 |
| A 活躍 | 距最後有效活動未超過 30×24 小時 | 維持服務品質，不因多球重複計人 |
| S 待關懷 | 不屬 N/A，距最後活動（無活動則距建立日）>30 且 ≤90 天 | 分出 PREVIOUSLY_ACTIVE 與 NEVER_ACTIVATED，區分沉寂及尚未啟動 |
| L 流失 | 距最後活動／建立日 >90 天，或目前關係已關閉 | 作為回訪或關係確認線索；不是永久資格處分 |

恰好第 30 天仍在活躍／新進窗口，第 90 天仍為 S，下一毫秒進入下一區間。S 的「從未啟動」子類別補足舊版只寫 previously-active 的空白，防止第 31–90 天無法分類。

有效活動為已存在的 Order.paidAt（ORDER_PAID）或 MonthlyRecognitionSchedule.recognizedAt（REPURCHASE_RECOGNIZED；含保存認列歷史的 REVERSED）。被退貨的歷史付款仍代表曾有經營互動；它不代表淨銷售額。登入、瀏覽、分享、訊息已讀不會單獨產生 A。事件發生當時的 QualificationHolderHistory 必須唯一吻合；缺少或重疊證據時整份新快照停止產生，保留上一份快照並隨時間顯示過期。

各狀態率＝狀態人數／納入的去重 Person 數。無分母回 null，畫面顯示「—」。

## 十二代雷達與分母

起點不計入第 1 代；其直接子節點為第 1 代。最多第 12 代，第 13 代不納入。圖上 12 條軸各代表一代；綠色圓點代表資格活躍率，橙色方點代表重購率。缺資料不繪點。這是各代百分比雷達，不是七項權重的蜘蛛圖。

| 指標 | 分子／分母與來源 |
| --- | --- |
| 人員球數／系統球數 | 分開計數，不把系統球納入人員比率 |
| 自然人數 | 每代去重 Person；整個 12 代範圍再全域去重，不能把每代人數直接相加 |
| 資格活躍率 | 目前 EFFECTIVE 且快照時點有有效 ActivePeriod 的人員球／人員球數；期間左閉右開 |
| 重購率 | 最近 30 天有 REPURCHASE 付款或訂閱月認列的人員球／人員球數。重複事件與多次重購只算一球 |
| 新增占比 | 最近 30 天新建人員球／目前範圍人員球；這是新增占比，不是淨成長率 |
| NASL 風險率 | S+L 去重 Person／範圍去重 Person；若有人無法分類，回 null |
| 雙軌人數平衡 | 2×min(左區人員球,右區人員球)/(左+右人員球)，0–1；非業績或 Carry 平衡 |
| 代數活躍覆蓋 | 活躍率 ≥55% 的非空代數／全部非空代數 |

左／右區沿起點第一條 Binary 邊傳遞，後續各代維持同一側的歸屬。Sponsor 不從 Binary 推導；Sponsor 頁的 Binary Balance 是 null。

## 熱度與健康權重

樣本小於 5 個人員球：INSUFFICIENT_SAMPLE，仍可看原始數據但不評級。大樣本依最嚴重條件優先：

1. CRITICAL：資格活躍率 <30%，且 NASL S+L 風險率 ≥50%。
2. COLD：資格活躍率 <40%。
3. COOLING：資格活躍率 <55%，或較可比快照下跌至少 10 個百分點。
4. HOT：资格活躍率 ≥75%、重購率 ≥65%，且有可比快照證明活躍率未下跌 10 個百分點。
5. 其餘為 WATCH。缺少約 30 天前比較資料不判為 HOT。

可比快照：同一根球、同一樹、同一政策，擷取 30～31 天前最新一份；不插值。GROWING 為獨立旗標，新增占比與重購率都比可比快照提高至少 5 個百分點。

健康權重沿用核准版：資格活躍 25%、重購 20%、新增 15%、低沉寂風險 15%、雙軌平衡 10%、代數活躍覆蓋 10%、有效互動 5%。除新增外直接使用 0–1 比率；低風險＝1−風險率；新增得分＝min(1,新增占比/10%)。不把不同量綱直接相加。

有效互動事件來源尚未建立，該 5% 維持 null。總分僅在全部權重的輸入都有證據時產生；缺值不補零、不重新配重。畫面同時呈現每個分項與資料覆蓋率。這一版尚不宣稱完整健康總分可用。

## 歷史、鮮度與權限

每次重建產生不可覆寫的資料庫快照，包含政策副本、版本、asOf、來源摘要 hash、分項与內部狀態。重建是目前 Core 的有界 repeatable-read 掃描，不接受任意歷史 asOf。這不是增量 Outbox projector，也不宣稱能用已變動的現況重造任意歷史。

NASL 轉換以相鄰的已保存同政策快照比較：共同 Person 才進轉換矩陣；新加入者另計；S/L→A 為再活化，非 L→L 為本次轉入流失。前期 A 中仍是 A 的比例稱「原活躍者仍活躍」，不冒稱月留存。每日歷史預設最近 90 天，可指定台北日期 from（含）、to（不含），最多 366 天；僅比較指定政策版本，缺日不補零。另提供固定月末母體的 M0–M12 同期群留存，詳見 PHASE2-DELIVERY.md。

lagSeconds 表示距快照擷取時間的秒數，不是已證明所有外部事件抵達的延遲。>900 秒顯示 STALE。提供手動更新、部署刷新腳本與預設關閉的 API 背景更新服務；可查啟用狀態、最近成功與持久化快照鮮度。尚未啟用運轉，不能宣稱已達 15 分鐘 SLO。

讀取：SUPER_ADMIN、MEMBERSHIP_OPS、FINANCE、COMPLIANCE_AUDIT。重建僅 SUPER_ADMIN；逐代證據 ID 不開放 FINANCE，每次上限 100 筆。無任何一般分析匯出 API。來源只讀必要欄位，不複製姓名、電話、身分證、銀行與文件。內部 Person／Qualification ID 仍是可連結識別碼，不視為匿名資料。一般回應不洩漏內部 Person 狀態映射。

上限：每次來源 Person、Qualification、各樹與 system pool 各 25,000 筆；付款、認列、持球歷史、ActivePeriod 各 100,000 筆。任何來源超限直接停止，絕不截斷後把結果標為完整。大型資料應改增量分區投影。資料表防 UPDATE/DELETE 的 trigger 為保留歷史；正式保留／清除政策需另有受控維護程序，不能把 append-only 誤解成永久無限保存。
