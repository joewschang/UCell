# NASL 第二階段：歷史、固定同期群與自動更新

完成日期：2026-09-18。延續 UCELL-MGMT-2026-09-v1，不改變資格、獎金、訂單或結算。

## 已完成

- history / transitions / cohorts 可選台北 from（含）、to（不含）與精確政策版本；日期必須成對、有效、最多 366 天，不接受未來日期或其他參數。預設 90 天，目前頁面留存區預設 365 天。
- policy-versions 回傳目前及已保存版本；目前概況與雷達僅讀目前政策，歷史不混合政策。
- cohorts 現在回傳固定同期群留存，取代第一版每日現況別名。metricVersion=COHORT_FIXED_MONTH_END_V1；此為 API 回應契約變更。
- 管理頁新增独立歷史區，日期／政策套用後查詢每日數值與留存熱圖，可切換活躍占比／原活躍者留存率；其他概況／組成圖維持原本範圍。
- GET refresh/status 顯示程序啟用、執行、最後整輪成功、錯誤碼，以及資料庫保存的各範圍快照鮮度。重啟會清除程序狀態，持久化快照仍保留。

## 同期群的管理定義

只使用台北各月最後一個日曆日實際保存的最後一份快照；這不是整個月底最後一瞬間的完整歷史重建，畫面保留真實 asOf。月份尚未結束不產生終值。

母體為該加入月份在月底快照中的自然人，加入日期仍採 Person.createdAt 代理。M0 是加入月，M1 是次月，最多 M12。加入月或觀測月底無快照時回傳缺資料原因，不用月中或目前狀態代替。

同期群活躍占比 = 觀測月 A 人数 / 加入月底固定全部人數；原活躍者留存 = 加入月底 A 且觀測月底仍 A 人數 / 加入月底 A 人數。後續新加入記錄不加入分母。任何母體成員缺少觀測，結果標 PARTIAL 並將比率設 null；分母零亦不計算。這是月末狀態留存，不代表期間內持續活躍。一般 API 不暴露成員 ID 或內部 states。

## 部署設定

背景更新服務在 API 程序中執行；預設關閉。本次沒有改動日常資料庫、啟用排程或部署正式環境。先依環境流程套用第一階段 analytics migration，再啟動新版 API。

| 環境變數 | 定義 |
| --- | --- |
| UCELL_ANALYTICS_REFRESH_ENABLED | 僅 true 啟用；預設 false |
| UCELL_ANALYTICS_REFRESH_SECONDS | 每輪完成後等待秒數；60–600，預設 300 |
| UCELL_ANALYTICS_REFRESH_ROOTS | 逗號分隔 Qualification UUID，最多 5 個；GLOBAL 自動包含 |

唯讀 DEV 不能啟用。每範圍最多 3 次嘗試，重試沿用同一時間桶 UUID；各程序使用相同政策／間隔設定時去重，資料庫 advisory lock 阻擋同時寫入。單一程序不重疊執行，逐範圍失敗仍繼續其他範圍；關閉等待正在執行的工作。成功與 SYSTEM audit 同交易提交，錯誤僅輸出有限管理錯誤碼。已有外部刷新腳本時應擇一配置，避免重複扫描。

這仍是有界來源掃描，不是 Outbox 增量投影。超過來源上限、事件持球歸屬缺漏均拒絕產生新快照；保留上次快照與 STALE。長時間掃描及多範圍會增加週期，15 分鐘 SLO 仍須在部署環境量測。
