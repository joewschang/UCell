# Period-close durable job foundation

Scope: expanded autonomous queue item 3, under the existing Period Close Orchestrator / Outbox design. This is an internal persistence and execution boundary, not an enabled scheduler or an authorization API. No Stage/Production deployment.

Migration 108 adds immutable `integration.period_close_job` manifests and `period_close_receipt` records. A manifest pins settlement kind, exact period, rule version, verified parameter snapshot, prerequisite job IDs, requesting actor and approval reference. Its unique kind/period/rule identity prevents duplicate jobs. One Outbox event is created atomically with admission; concurrent duplicate admission returns the existing request, while changed prerequisite/approval semantics are rejected. Admission requires a calendar-preparation callback; integration tests call the real approved-calendar/cutoff validator. No public caller can submit these jobs yet.

Prerequisites must already exist, share the rule version, and lie within the requested period. Because manifests cannot be updated or deleted, newly admitted jobs cannot introduce cycles. Matching additionally requires a Binary job for the identical period. Explicit dependency lists are a mechanism, not a complete economic dependency planner: recognition readiness, multiple weekly jobs under monthly close, Welfare and payout preparation still need orchestration policy and integration.

`claimPeriodCloseJob` waits for all prerequisite receipts before claiming the existing Outbox lease. Dependency polling does not increment attempt counts. Claims use the existing compare-and-set ownership token; expired owners cannot execute or overwrite a newer result. `processPeriodCloseJob` retains the Outbox row lock through its transaction. The handler must perform its economic work using that transaction. Before committing, the core verifies the actual sealed result's kind/source, period, rule and parameter hash against the manifest. Economic writes, an immutable receipt and Outbox acknowledgement commit together. Errors roll back all three; existing fenced Outbox failure/retry handling remains available. Parameter drift fails closed rather than silently calculating under new rules.

Real-engine tests reuse Referral/Binary/Matching/Global services through a transaction facade so their work remains under the lease transaction. Empty-period governance cases cover concurrent admission/claim, prerequisite blocking, request conflicts, lease replacement, rollback/retry, parameter drift and append-only records. Funded cases reconcile Referral 15 + 15, Binary 10, Matching 1 from Binary 10, and Global 4 / Reservoir A 6 with their committed job receipts. Existing direct-service process-kill tests remain separate evidence; they do not yet certify a launched job worker.

The Worker does not yet consume `PERIOD_CLOSE_REQUESTED`; its explicit event filter leaves these requests untouched. There is no automatic scheduling, Admin job endpoint/UI, Welfare job or payout export automation in this slice. Follow-up work must supply authenticated/audited admission, a calendar/dependency planner and due-recognition gate, production adapters using the supplied transaction and pinned parameters, worker dispatch/restart evidence, and operator visibility/retry controls. Finance approval/export remains a human gate.
