# Ball Number V2：各樹獨立生成序號

生效規則日期：2026-09-25。依本次使用者授權取代一般球以 `binaryPositionNo - 3` 編碼的規則；財務、推薦及二元樹位置規則不變。

## 編碼與生命週期

- 公司起始三球保留 `TreeCode + X + PAD6(position)`，例如 `AX000001`、`AX000002`、`AX000003`，不占用一般序號。
- 一般會員資格與其他公司持有球共用各樹序號：`TreeCode + PAD6(sequence)`。每樹從 1 開始，互不影響。`A000001` 表示 A 樹第一個一般球，不代表位置 4。
- 使用者確認保留現有樹代碼格式：`^[A-Z][A-Z0-9_-]{0,39}$`。T 是完整樹代碼，不限一字元。
- 序號前置補零至少六位，超過 999999 時自然延長，不截斷、不循環使用。儲存採 PostgreSQL bigint；到達 bigint 上限須拒絕配號。
- 新球於成功安置入樹的同一交易內配號。未安置資格可保持 `ballNo = null`。預覽不配號、不占號，`expectedBallNo = null`；正式球號以提交成功收據為準。
- 所有權轉讓、會員球移轉公司、公司再轉讓、停用或退出均不重新配號，不回收已提交的序號。
- 本次不新增直接建立公司一般球的業務入口；既有公司接收／再轉讓流程保留原號。未來直接建立公司一般球必須共用相同配號器。
- 同樹並發配號由資料庫鎖與原子計數器序列化。序號代表配號交易順序，不代表用戶請求抵達時間。
- 同一資格重試取得同一筆配號；跨樹重配拒絕。安置交易失敗時，計數器、配號紀錄、位置及球號一同回滾。

## 系統與資料庫

`organization.ball_no_counter` 保存每樹最大已使用序號；`organization.ball_no_allocation` 保存資格、樹、序號、記錄時間及規則版本，禁止更新或刪除。`organization.allocate_ball_no` 是共用配號器。

`qualification_ball_no_integrity` 改為驗證一般球號對應配號紀錄與實際樹；起始三球仍驗證保留位置。球號唯一及不可變更限制保留。`binaryPositionNo`、位置父子公式、安置證據、UUID 主鍵不變。

一般球格式化 `ballNoFor(treeCode, sequence)` 的第二參數現在是配號序號；起始三球改用 `bootstrapBallNoFor(treeCode, position)`。禁止再從球號推導位置、左右區或推薦順位。

## 既有資料與發布

1. 保留全部既有球號，不改寫歷史稽核資料、訂單推薦球號快照或對外參照。
2. 遷移以完整樹代碼長度截取一般球數字尾碼，建立 `LEGACY_POSITION_V1` 配號紀錄；不宣稱舊號代表歷史生成順序。
3. 各樹計數器以一般球最大既有尾碼初始化，不使用球數。無一般球的樹從 0 開始。歷史缺號不補發。
4. 新配號紀錄標示 `TREE_SEQUENCE_V2`。回填的 `allocated_at` 是遷移記錄時間，非原始建立時間。
5. 以新增 forward migration 發布，不改寫已執行的舊 migration。先備份目標資料庫，暫停安置寫入，執行 migration，再部署新版 API；舊版 API 的位置球號算法不得與新規則混用。
6. 執行 `pnpm p0:reconstruction:dry-run`，驗證球號／配號紀錄、位置與唯一性；恢復安置服務後以新版預覽與收據操作。
7. 新號一旦發布，不得只回滾到舊配號程式；應以相容 V2 的修正版本恢復服務。

## 驗證範圍

公司三球保持原號、跨樹獨立配號、同樹並發唯一、同資格重試、跨樹拒絕、交易回滾、六位成長、位置與序號解耦、深層樹安置、空值預覽、既有資料續編、會員／公司移轉保留號碼，以及 Admin 預覽與收據畫面。

本文件描述規則；實際執行環境與驗證結果另記於 `BALL_NUMBER_SEQUENCE_V2_VALIDATION.md`，避免把原始碼修改視為正式環境已部署。

本機若有其他功能尚未套用的 migrations，可設定明確的本機 `DATABASE_URL` 後執行 `node backend/scripts/ball-sequence-migrate-local.mjs`，只套用本次 migration。該工具拒絕遠端資料庫；正式發布仍使用既有部署流程。
