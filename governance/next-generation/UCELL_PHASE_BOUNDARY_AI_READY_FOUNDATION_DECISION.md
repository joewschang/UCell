## 5. Minimal Semantic Runtime boundary

After SG-A1, implement only what is necessary for governed definitions and future compatibility:
- Definition/version;
- FactDefinition;
- MetricDefinition;
- DatasetDefinition;
- RuleDefinition;
- ScopeDefinition;
- PrivacyDefinition;
- DataLineage;
- DefinitionDependency;
- certification/source mapping/conflict metadata;
- deterministic seeds/hash/drift controls;
- read-only Data Governance views/API/UI as justified.

Do NOT create AI session, prompt, memory, tool registry, embedding/vector or LLM-specific tables in Phase 1.

## 6. Phase 2 — AI-Native Analytics

Phase 2 may begin only after Phase 1 closure gates are satisfied and separately approved.

Planned sequence:
Analytics Projections → Governed Query Engine → Runtime Data Firewall → Admin Analytics Center → Admin AI Data Assistant READ ONLY → Red Team/Security Closure → Organizational Learning/Development Request Bridge.

No write actions in initial Phase 2 AI release.

## 7. Phase 3 — governed action proposals

Only after read-only AI has security closure may future work consider:
AI proposal → Human confirmation → Governed command.
Direct autonomous Production mutation is not approved by this decision.

## 9. Cross-layer governance

A current feature change still MUST assess AI Brain impact under UCELL_CROSS_LAYER_CHANGE_GOVERNANCE_RULE_V1.
Valid AI Brain dispositions include VERIFIED_NO_CHANGE or UPDATED_FUTURE_DESIGN.
This does NOT authorize AI runtime implementation.

## 10. Success criterion

Phase 1 succeeds when UCell is operationally stable, economically correct, semantically governed, source-audited/certifiable, privacy-safe and ERP-handoff-ready — not when an AI chat box exists.
