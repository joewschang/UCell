# 獎金機會通知

實作日期：2026-10-31。此功能僅新增機會試算與通知，不寫入獎金、錢包、可付款項或改變 Carry。

## 觸發與金額

- `applyGpvImmediateEffects`：在 GPV 事件的同一交易，依歷史推薦路徑與資格，建立推薦／均等獎金機會。即時金額明示為獎金池係數調整前的試算。
- Referral K0、Binary K1、Matching K2 結算：產生結算期機會明細。未活躍、等級不足、有效直推不足可同時存在；同一來源只記一個金額。
- 等級不足覆蓋原先直接略過的均等獎金代數；使用能解鎖該代的最低等級。這是所列機會的局部試算，不是完整升級收益模型，不試算提高所有既有獎金比率或未來 Carry 的影響。
- 結算試算將同一資格本批次的漏失理論額加入池分母重算 K，扣除其既有獎金因 K 改變的差額，再按理論額分攤。不同會員的試算屬不同情境，不應合計成公司實際負債。
- 唯一鍵含事件／批次、資格、來源、獎金種類及代數。即時提醒與結算更新為兩個不同階段；重跑同一階段不重複新增。
- 未達 NT$0.005 的機會不通知；持有人使用資格判定當時的歷史持有人，缺少歷史資料時交易失敗，不回退至目前持有人。公司資格及無自然人持有人的法人資格不發會員 LINE 通知。

## 發送與查閱

`ledger.bonus_opportunity`、站內通知、LINE delivery 與 outbox 同交易建立。worker 使用獨立的 outbox lease，固定訊息、綁定與 LINE retry UUID；網路錯誤、429、5xx 延後重試。409 且包含已接受 request ID 視為服務端已接受，不表示會員已讀。

第一次發送後最多重試 23 小時；不跨越 LINE 的 24 小時 retry-key 保證。綁定撤銷後不改投其他帳戶；未綁定、綁定不唯一與永久失敗保留紀錄。未設定 token 時不呼叫外部 API，等待設定後重試。站內通知仍可查看。

LINE retry 語意依據：https://developers.line.biz/en/docs/messaging-api/retrying-api-request/

會員訊息中心沿用 AWARD 分類，以已發布訊息呈現「獎金機會未取得通知」。後台獎金頁選擇資格後可查看原因、試算依據、來源及發送狀態；API 為 `GET /admin/bonus/qualifications/:qualificationId/opportunities`，沿用獎金管理角色限制，最多 200 筆。

## 退款更正

退款重算收斂並正式過帳時，對受影響的來源與結算批次標記 `reviewRequired`，追加更正通知撤回舊估值。原訊息與金額保留供稽核；尚未送出的舊估值停止發送。更正通知明示「目前尚無重新確認的機會金額」，不提供未經完整重算的替代數字。完整退款後機會金額重新試算仍未實作。

## 部署與驗證

先套用 `20261031090000_bonus_opportunity` migration，再發布 API、worker 與後台；會員端沿用既有訊息中心。既有已完成結算不自動回補通知。worker 需要 `LINE_CHANNEL_ACCESS_TOKEN`（亦相容 `LINE_MESSAGING_CHANNEL_ACCESS_TOKEN`）及有效 LINE 綁定。

主線整合遵循既有 PR CI、隔離 PostgreSQL 回歸及發布流程。正式機存在較新修正，發布必須以目前映像為基底套用此次變更，保留現行功能。發送測試使用模擬 API，未發送真實會員訊息。

已完成本機驗證：完整後端編譯、後台型別檢查、69 組後台測試（249 項）、全量 migration 與 162 項資料庫基準。完整 API 回歸及遠端 CI 結果於 PR 補充。正式發布另需紀錄主線 commit、映像 digest、資料庫備份與實際部署後健康檢查。
