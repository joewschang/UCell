# UCell OpenAPI / SwaggerHub governance

## Authority and publishing workflow
The NestJS source and locally generated backend/openapi.generated.json remain the sole production contract source. SwaggerHub is a private, publish-only documentation/collaboration target. Never download a SwaggerHub edit into application source, generated artifacts, migrations, or an approved baseline. Review cloud suggestions as a normal source-code PR, regenerate locally, and run the gates.

Existing destination: https://app.swaggerhub.com/apis/ragetech/ucell-api/1.0.0. The first CI candidate is compatible minor version 1.1.0, including the latest integration branch additions and the missing orderId annotation; runtime URLs stay /api/v1/.
Owner: ragetech; API: ucell-api. API versions remain private and editable (SwaggerHub's immutable Published lifecycle is separate from this workflow's documentation publication). Do not use force-update, public visibility, outbound code-generation integrations, or bidirectional synchronization.

.github/workflows/swaggerhub-sync.yml validates PRs and pushes without publication credentials. The verify job builds frozen dependencies, regenerates OpenAPI, scans both candidate and baseline, runs pinned oasdiff 1.32.1 validation and strict WARN/ERR breaking detection, publisher regression tests, the TODO/security policy gates, and the full isolated API Jest suite (contract, authorization, RBAC and evidence-security tests). An ephemeral CI PostgreSQL service is the only database used; no Stage/Production service or credentials are available.

Only a successful verify job can upload the exact generated artifact and its commit/hash-bound gate receipt. Publication is limited to the repository default branch on push or workflow_dispatch and the protected swaggerhub-docs environment. The publisher has no application dependencies or database credentials. It checks every gate, commit and artifact hash before any network request, re-scans against the CI key, requires private visibility, uploads with isPrivate=true&force=false, then rechecks visibility and compares canonical JSON after readback. Authentication/permission failures stop immediately. Network failures, timeouts, 429 and transient 5xx responses get four bounded attempts. Failure is nonzero, recorded and retained; never continue-on-error.

Cloud content is observed only in memory for verification and previous hashes, never written over local source. A changed cloud artifact is replaced by the gated local source; its previous hash is recorded to support investigation. The publication receipt includes separate raw-byte hashes for generated and cloud artifacts and canonical hashes to explain harmless whitespace/key-order differences.

## Baseline and breaking-change policy
baseline.openapi.json is the 147-path 1.0.0 artifact previously verified equivalent to SwaggerHub and accepted as this task's baseline. policy.json pins its exact byte hash. Regular PR/push workflows reject edits to an existing baseline or diff configuration relative to the trusted base commit; initial bootstrap requires owner review. CODEOWNERS protects governance, workflow, publisher and generator files. Enable required code-owner approval in branch protection; the file alone does not enforce reviews.

Comparison inputs are separately hashed views: identical case-insensitive duplicate header declarations are deduplicated (conflicting duplicates fail), and missing legacy URI placeholder declarations are represented as mandatory strings. Original baseline and generated bytes remain untouched. This explicitly accounts for the old orderId documentation omission. Candidate validation runs before normalization. Real URI changes and stricter parameter/schema constraints remain detectable; authentication weakening also fails an explicit security comparison.

No automatic waiver is supported. Removed operations, tightened required inputs, incompatible schemas/status/security changes and all oasdiff WARN/ERR findings block publication. Do not reset the baseline or suppress findings to make CI green. Review documentation-only discrepancies against actual server/client behavior and record an explicit governance decision before a separately reviewed baseline maintenance change. The normal workflow intentionally does not provide a baseline-promotion bypass. API/security owners must retain compatibility for existing /api/v1 clients; material behavior changes require a separately scoped migration design.

## Versioning
The OpenAPI info.version is the SwaggerHub version and must use 1.MINOR.PATCH. Increment PATCH for documentation-only corrections, MINOR for compatible additions; retain old versions. Never infer /api/v2 from Experience v2. Every path must stay under /api/v1/. The published document's version must equal the generated artifact's version. A semver change alone never overrides the breaking-change gate. Existing immutable SwaggerHub versions cause visible failure: select a reviewed new documentation version rather than force-update or unpublish.

## Evidence / Release and RC
gates.json records PASS/FAIL for every prerequisite with source commit, approved baseline hash, generated path count, HTTP operation count, named component schema count, raw artifact SHA-256 and canonical SHA-256.
publication.json and backend/release/SWAGGERHUB_SYNC_EVIDENCE.json record the exact generated hash separately from the readback artifact SHA-256/version, private status, canonical equality, timestamp, CI run and prior cloud hashes.
The generated OPENAPI_CONTRACT_REPORT.md is retained in the publication artifact. The repository report records implementation verification and blockers, not invented CI PASS results.
RC promotion downloads evidence from a successful swaggerhub-sync.yml run for the same commit; release-check rejects missing, failed or stale receipts. Workflow success and protected GitHub artifact provenance are required; a hand-edited JSON PASS is not acceptable. Publication failure blocks documentation readiness, never rolls back authoritative application data.

## Ownership / permissions and activation
API owner: repository CODEOWNER @joewschang; review contract changes and baseline decisions. Security owner: designated organization security reviewer; review authorization, secret scanning and credential changes. Release owner: designated swaggerhub-docs environment approver; approve documentation publication after gates. Do not invent team memberships.

Repository administrators must configure:
1. Protect the default branch with required OpenAPI verify status, code-owner review, and no bypass for ordinary authors.
2. Create swaggerhub-docs with required reviewers (prevent self-review) and restrict deployments to the protected default branch. This is a documentation credential boundary, not an application deployment.
3. Store SWAGGERHUB_API_KEY only as a secret in that environment, using a dedicated account with the minimum SwaggerHub role that can edit this private API. Never store it as a variable, workflow input, artifact, .env committed file, or OpenAPI example.
4. Only the publish step receives that secret. PRs, forks and build/test jobs must never receive it.
5. Remove edit rights for ordinary documentation collaborators where supported; use comments/suggestions. Keep existing organization visibility restrictions. Do not copy personal Codex OAuth credentials into CI.
These hosted controls and CI credentials are not provisioned merely by adding workflow files. A missing key fails publication explicitly.

## Credential rotation
Rotate on the organization's scheduled policy and immediately after suspected exposure or personnel/access changes. Create the replacement for the dedicated publishing identity, replace the protected environment secret through approved secret administration, run the same gated workflow on the default branch, and verify private visibility/readback evidence. Revoke the old key after verification (immediately first if compromised). Record actor/time/key identifier only, never key material. Failed rotation must leave the application unchanged and surface as a failing publication run.

## Secrets and examples
Scan the complete JSON, not just schemas. Reject known token/key/password encodings, credential-bearing URLs, private keys, exact CI credential matches, external references/examples, and SECRET_NEVER_AI anywhere. Only reviewed synthetic literal examples/defaults are permitted; credential fields may contain no literal example except [REDACTED]. Scanner failures log a code, never the offending value. Do not publish the spec artifact unless the scan passed. A scanner is defense in depth; owners must also review generated descriptions, examples and extensions before approval.

## Rollback / re-publish
Do not roll back or migrate application data because documentation publication failed. Keep the last verified private SwaggerHub artifact and the failed run evidence. For transient failure, rerun failed jobs for the same commit: the same bytes are uploaded idempotently and verified again. For source corrections, use a reviewed PR and the normal gates. To restore a prior documentation version, re-run the full workflow on a reviewed default-branch commit that deliberately regenerates that contract, or reference the retained prior private version. Never fetch cloud content as rollback source. Concurrent publishers serialize on the API-wide concurrency group. Do not auto-delete cloud versions or issue force updates.

## Local verification
Install the checksum-pinned oasdiff 1.32.1 executable and set OASDIFF_BIN to its absolute path. From backend run node --test scripts/openapi-governance.test.mjs, then node scripts/openapi-governance.mjs gate with a local disposable PostgreSQL control connection. gate may create/drop only uniquely named local test databases through the existing isolated test runner. Local runs cannot invoke the CI publisher.
