# 訂單狀態追蹤與外部匯入格式 v1

版本：1｜2026-10-23｜時間顯示：Asia/Taipei。

## 檔案契約

第一版使用 UTF-8 CSV（可含 BOM），逗號分隔、第一列固定欄位名稱。一列代表一筆物流事件。同一訂單有多件包裹時分列填寫；同一包裹的多次狀態變更也分列填寫。最多 500 筆事件、256 KiB。支援雙引號包住含逗號或換行的文字，雙引號以兩個雙引號跳脫。

| 欄位 | 必填 | 格式／用途 |
|---|---|---|
| format_version | 是 | 固定文字 `1` |
| source_system | 是 | 來源系統代碼；英數字、底線或連字號，1–40 字，如 `ERP` |
| event_id | 是 | 來源系統的固定事件編號，1–100 字；重送同一事件必須沿用原編號 |
| order_no | 是 | UCell 訂單編號，1–18 位數文字；不是會員編號，也不是資料庫 UUID |
| fulfillment_key | 是 | 後台已存在的配送批次代碼，最多 200 字 |
| carrier | 是 | 與後台已登錄貨運單的物流商代碼完全一致，最多 80 字 |
| tracking_no | 是 | 已登錄的貨運單號，文字，最多 200 字；保留前導零 |
| status | 是 | 下表列出的英文狀態代碼 |
| occurred_at | 是 | 事件發生時間，ISO 8601，必須含時區，例如 `2026-10-23T14:30:00+08:00` |
| external_order_no | 否 | ERP／外部訂單編號，最多 100 字，供追溯，不代替 UCell 訂單編號 |
| note | 否 | 事件備註，最多 250 字；不要填入收件人姓名、電話、地址等個資 |

所有編號在 Excel 必須設為「文字」。建議使用 Excel 的「資料 → 從文字/CSV」匯入，避免直接開啟後遺失前導零、轉成科學記號。匯出時選 CSV UTF-8。空值留空，不填 NULL。不得以公式產生識別欄位。

## 物流狀態與變更規則

| 代碼 | 中文 | 可接續的狀態 |
|---|---|---|
| READY | 待建立貨運單 | LABEL_CREATED、CANCELLED |
| LABEL_CREATED | 貨運單已建立／待攬收 | PICKED_UP、CANCELLED |
| PICKED_UP | 已攬收 | IN_TRANSIT |
| IN_TRANSIT | 配送中 | DELIVERED、DELIVERY_FAILED、RETURNING |
| DELIVERY_FAILED | 配送異常 | IN_TRANSIT、RETURNING |
| RETURNING | 退回中 | RETURNED |
| DELIVERED | 已送達 | 結束，不可倒退 |
| RETURNED | 已退回 | 結束，不可倒退；不等於退款完成 |
| CANCELLED | 配送已取消 | 結束，不等於訂單取消 |

只更新已登錄且精確匹配「訂單編號＋配送批次＋物流商＋貨運單號」的包裹。新訂單、新貨運單仍由既有訂單與出貨流程建立，維持裝箱、序號及 ERP 核對。檔案不變更收款、退款、商品庫存或獎金帳本。會員前台讀取同一份包裹配送狀態。

不允許跳過必要事件，例如待攬收直接變已送達。外部系統應提供中間事件，系統按同一包裹的事件時間依序檢查。時間晚於目前狀態才可推進；舊事件跳過並提示。重複來源與事件編號且內容相同時跳過；同編號內容不同則阻擋。來源事件編號必須在來源系統內唯一。

## 後台操作設計

商務選單新增「訂單狀態追蹤」，保留「訂單與收款」及「出貨與序號核對」作業入口。

1. 頂部狀態卡：全部、待付款、待出貨、待收貨、待評價、已完成、配送異常、其他／退貨。顯示訂單數，非包裹數。
2. 搜尋訂單編號、貨運單號、商品；分頁顯示。每張訂單呈現付款與配送兩種狀態，避免把已付款誤認為已出貨。
3. 展開訂單可看商品、每個配送批次、貨運單號及按時間排列的物流歷程；分批配送逐件呈現，全部有效批次送達才列入待評價。
4. 匯入區：下載範本 → 選檔／預覽 → 確認匯入 → 結果。預覽列出行號、訂單、原狀態、新狀態及原因；只要有錯誤，整批不寫入。
5. 確認前再次檢查資料版本；有人或 ERP 更新過狀態時，要求重新預覽。成功顯示新增與略過筆數，保留操作人、時間、檔案摘要及事件證據，重試不得重複寫入。
6. 管理員與訂單作業角色可匯入；財務及稽核角色可查詢，不能藉此修改物流狀態。

## 範例（虛構資料，不能直接當正式資料匯入）

```csv
format_version,source_system,event_id,order_no,fulfillment_key,carrier,tracking_no,status,occurred_at,external_order_no,note
1,ERP,DEMO-0001,999999999999,DEMO-BATCH,OTHER,000012345678,PICKED_UP,2026-10-23T09:00:00+08:00,ERP-DEMO-001,範例已攬收
1,ERP,DEMO-0002,999999999999,DEMO-BATCH,OTHER,000012345678,IN_TRANSIT,2026-10-23T10:00:00+08:00,ERP-DEMO-001,範例配送中
1,ERP,DEMO-0003,999999999999,DEMO-BATCH,OTHER,000012345678,DELIVERED,2026-10-23T14:30:00+08:00,ERP-DEMO-001,範例已送達
```

## 驗收要點

UTF-8 中文、前導零、含逗號備註、跨時區事件、分批配送、來源重送、同事件內容衝突、未知訂單／貨運單、狀態倒退、缺少中間事件、預覽後競態、整批原子寫入、無匯入權限、會員前台同步顯示，均須驗證。
