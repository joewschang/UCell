# UCell 管理後台營運體檢與改善方案

2026 年 11 月 12 日　｜　適用於營運值班、會員服務、訂單、財務及主管

## 範圍與結論

本次盤點正式版的 50 個側欄入口，另檢查登入、建立申請、正式會員紙本申請及健康中心舊入口，共 54 條路徑。使用隔離 API 回應驗證 390px 手機與 1366px 桌面的深淺色版。Chromium 涵蓋 216 組路徑與顯示條件，WebKit 手機版另有 108 組。檢查包含能否進頁、主要內容是否出現、頁面橫向溢位與瀏覽器錯誤。收款、角色權限、報表可讀性與跳頁另有情境測試。這些結果能驗證操作流程，實際業績與節省工時須由上線後資料衡量。

| 工作目的 | 涵蓋的選單與入口數 | 工作在哪裡結束 |
| --- | --- | --- |
| 決定今天先做什麼 | 營運總覽 2 | 從待辦類別進入案件，找到承辦角色與建議時限 |
| 受理入會及配置組織 | 會員管理 10、組織 3 | 核對本人或法人、收款與文件，再查資格及組織位置 |
| 產生與承接需求 | 活動 2、內容與客服 7 | 由活動、內容或客服進入對應服務，查看後續造訪與註冊 |
| 完成交易及交付 | 商品與訂單 9 | 追蹤出貨、退貨、重購與訂單狀態 |
| 驗算、對帳與撥付 | 獎金結算 4、財務對帳 3 | 以期別及來源交易核對歸戶、調整、對帳與付款批次 |
| 檢討表現與異常 | 營運分析 5、系統管理 5 | 從分享、PNASL、報表、AI 與稽核進入待追查的資料 |

## 本輪改善與驗證

| 優先 | 審查發現 | 已實作與驗證方式 |
| --- | --- | --- |
| P0 文件收件 | 文件收件匣載入分割模組時可重現 React 錯誤與空白畫面。 | 主程式和延後載入的模組共用同一份執行環境，版本一併更新。以相同瀏覽順序重新進入並檢查錯誤。 |
| P0 商品頁書籤 | 直接開啟或重新整理 /products 時，伺服器將頁面當作圖片目錄，回傳 403。 | 商品頁與商品圖片採不同路由規則。以 HTTPS 直接開啟與重新整理驗證，保留圖片讀取。 |
| P0 收款證據 | 切換訂單或付款資訊後，原勾選可能沿用。金額未知與明確零元需要各自處理。 | 核對勾選綁定當次訂單、金額、回報版本及付款方式。資料讀取失敗或金額未知時停用確認。全額減免獨立標示。 |
| P0 申請權限 | 稽核角色可看申請，建立申請屬另一項權限。 | 恢復系統管理員與會員營運建檔入口，稽核角色維持唯讀。建立按鈕與直接輸入網址共用權限判定。 |
| P1 進入工作 | 390px 寬手機的每日問候圖頁，主要內容原從畫面第 724px 開始。PNASL 與「早安圖」等日常用語難以找到。 | 手機選單預設收合，同頁內容起點移至 68px。保留依角色可見的連結，支援別名、複合關鍵字、鍵盤選取及清除。 |
| P1 業績與報表 | 期間欄位需要手打時間，讀取失敗可能顯示零。 | 可選今日、近七天、本月、上月或自訂日期。按台北時間以同一資料庫快照分幣別列出建立訂單、正額已付款訂單、退貨申報。三種 CSV 沿用已套用的日期，財務帳號只讀其授權資料。 |
| P1 待辦與成長 | 承辦原須逐一找待辦類別或重設分享分群。 | 首頁「優先處理」依逾時件數、待辦量列出最多三類。點選可帶著條件進入。分享區列出連結、有效造訪及新註冊，可直接看有造訪但尚無註冊的球。 |
| P1 查件與表格 | 正式會員案件的附件、收款與基本資料分散在長頁面。本批篩選容易被理解為全庫查詢。 | 會員主檔支援跨頁查找姓名、法人、代表人、手機及會員編號。若申請姓名尚未同步至主檔，可切到最近送審資料篩選。選案後可直達三個核對區。共用資料表明示已載入及符合筆數，提供欄位選擇、排序及分頁。 |
| P1 可讀性 | 深色雷達軸標籤對比僅 1.61 比 1，錯誤提示 2.53 比 1。兩種主題的歷史快照展開提示皆為 1.58 比 1。 | 在實際頁面量測，修正後分別為 10.61、7.64、12.07 比 1。另驗證通知範本、次要文字及快照狀態。 |

首頁的任務名稱、狀態與下一步入口放在同一列，讓承辦能直接接續處理。此安排參考英國政府設計系統的任務清單。[GOV.UK Design System — Task list](https://design-system.service.gov.uk/components/task-list/)

共用表格將搜尋、欄位顯示與頁次放在同一份資料旁，並保留列和欄標題的關係。此安排參考 IBM 對表格工具列、排序與分頁的設計。[IBM Carbon Design System — Data table](https://carbondesignsystem.com/components/data-table/usage/)

## 精簡人力的工作節奏

| 時點 | 負責人 | 操作與交接條件 |
| --- | --- | --- |
| 每日開班 | 當日值班，可由營運或會員承辦輪值 | 從「優先處理」先看逾時類別，按案件原始時間排先後。將跨角色案件附上案件編號、待核事項及下一位負責人。 |
| 每日處理 | 會員承辦、訂單承辦 | 會員承辦依申請清單核對人、件、款。資料不齊記錄缺件。付款資訊有差異交財務。訂單承辦接續已確認的出貨與例外。客服從通知中心查待處理紀錄及會員聯繫意願。 |
| 每日收班 | 值班、財務 | 交接尚未清除的逾時件與最早一件，列明原因及下次檢查時間。財務以收款、減免或退款的原始憑據確認差異處理結果。 |
| 每週 | 營運主管與同週值班 | 先看哪一群停在分享、造訪或註冊，再抽查實際案例。每週選一項可改動的內容、服務入口或回訪方式，記下適用對象與觀察期。 |
| 每個結算期 | 財務執行、現有主管或具權限者覆核 | 固定期別與資料截止時間，從結算工作核對獎金、退貨調整及撥款批次。保留交易、球號、期別與差異原因。有差異的項目回查後再決定是否放行。 |

同一人可兼任一般營運與客服。發生款項差異或需更正結算時，由具覆核權限的人查原始證據。每班使用既有清單及案件紀錄交接，主管只需追逾時、差異與例外。

## 上線後怎麼判斷改善有效

所有期間採台北時間。對同一期間重複查詢時保留資料截止時間。分母為零或來源未回傳時標示「無可用比例」。

| 指標 | 計算及期間 | 讀值後的動作 |
| --- | --- | --- |
| 逾時待辦占比 | 每日收班，該類別已超過建議時限的未結件數 ÷ 同時點該類別全部未結件數。 | 首頁已提供件數與逾時數。按類別看最早未結個案，找出缺資料或待交接的步驟。 |
| 分享承接 | 既有首頁顯示近 30 天建立的連結，以及這批連結截至更新時間的有效造訪與新註冊。有效造訪依瀏覽器去重。三項為數量，各自保留單位。 | 先分流到「已分享但尚無造訪」或「有造訪但尚無新註冊」球清單。每週固定同一時間記錄。 |
| 註冊後首次付款率 | 建議逐週追蹤。分母為該週新註冊且已觀察滿 30 天的會員。分子為其中註冊後 30 天內首次完成實際收款者，排除全額減免，依會員去重。 | 下一輪串接會員與付款事件後出數，同時列出分子與分母。另追退款及淨收款。 |
| 收款差異率 | 每週，該週完成初核且至少一項金額或付款方式不符的訂單數 ÷ 該週完成初核的訂單數，同一訂單只計一次。 | 先分實收、全額減免及退款，再檢查回報欄位、作業時序及證據。需可追溯初核結果才可彙總。 |
| 獎金差異結案率 | 每期，該期首次驗算發現的差異中，截至覆核日已有核對證據並結案的唯一差異件數 ÷ 該期首次驗算的唯一差異件數。另列未結金額。 | 財務查看尚未結案清單及影響金額，追至來源事件與歸戶。此版未建立此指標的自動報表。 |
| 查件耗時 | 建議上線首週建基線。每次從開啟清單至找到正確案件計秒，按會員審查、出貨、對帳分別記錄樣本數與中位數。找不到的次數另列。 | 兩週後比較相同任務與裝置，觀察主檔跨頁查找能否減少人工翻找。 |

## 下一輪投資順序

1. **觀察跨頁查件效果。** 分別記下主檔找到、改查最近送審資料才找到、兩者皆未找到的案件。若名稱落差頻繁，回查會員建檔及主檔同步流程，再決定是否擴充查詢。
2. **串起註冊、首購與退款。** 對同一批會員保存來源、註冊時間及首筆有效收款，再與訂單核對。保留未知來源與無法歸屬件數，才能比較活動或內容帶來的後續業績。
3. **減少例外交接。** 依兩期實際差異及等待時間，選最高頻原因增加自動比對、指定承辦與結案證據。優先處理能從原始事件重算、且已有明確判定規則者。


## 正式上線與驗證

2026 年 11 月 12 日（台北時間）發布。管理後台及 API 均已就緒，正式入口 100% 流量指向新版。

| 服務 | 正式修訂版本 |
| --- | --- |
| 管理後台 | `ucell-prod-admin--rel-261111181112-55fda8` |
| API | `ucell-prod-api--rel-261111180525-21f780` |

- 正式站逐頁檢查涵蓋 54 條路徑。Chromium 216 組、WebKit 108 組均通過進頁、標題、頁寬及執行錯誤檢查。瀏覽器以隔離資料模擬角色、案件、失敗及空值。實際裝置上的個別內嵌瀏覽器仍可能有差異。
- 253 項後台單元測試通過。另驗證台北跨月與閏年、三種 CSV 使用相同期間、稽核唯讀、現金與減免、重送及資料變更後須重新核對。寫入流程在隔離環境驗證。
- 正式 API 的唯讀核對期間是台北時間 2026/10/13 至 2026/11/11。依幣別比較正式報表與獨立 SQL 的建單、已付款及退貨件數與金額，三組一致。另已實查正式主檔搜尋及起始頁。
